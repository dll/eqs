# EQS 承接 CCIT 对外商业化/公司门户整合 功能清单 v1（交付 CTO）

> 文档性质：EQS 平台功能需求（对外交付/商业化/与 CCIT 官网协同），交 CTO（ccit-cto）统筹实现。
> 产出：ccit-ceo（CCIT-OPC 筹建线），2026-09-06
> 仓库：`MyProjects\eqs`（dll/eqs.git）
> 关联文档：`docs\EQS-PMA承载平台功能清单-v1.0.md`（商机采集/承接/PMA 内部运营后台，本清单的"商机域以它为准"）。
> 定位区分：上一份 = **内部（PMA 商机接入 + 全生命周期运营后台）**；本清单 = **对外能力出口（CCIT 公司官网整合、承接意向的对外表达、EQS 作为 CCIT 门面产品）**。

---

## 0. 背景与目标

EQS 当前为**已上线、多端（admin/client/server）的在产平台**，端点覆盖 auth/短信/微信/支付/文件/项目进度/AI 分析/i18n 等。

用户规划里 EQS 承担双重角色：
1. **内部**：PMA 的商机承接与项目管理运营平台（详见 PMA 承载清单）。
2. **对外/门户整合**：作为 CCIT 公司**展示与承接能力的一面**，与 CCIT 官网（`https://…/ccit/`，见 CCIT-官网功能清单）在**可视化/入口/管理**上打通；帮助 CCIT 展示"我们能承接什么、怎么做"。

本清单界定 **对外出口与官网整合** 的功能域，交付 CTO 评估实施 —— 哪些并入 EQS 现有工程、哪些只做只读出口/接口，由研发方案裁定。

---

## 1. 对外能力出口（EQS ↔ CCIT 官网）

| 编号 | 需求 | 说明 | 建议 |
|---|---|---|---|
| X1 | EQS 入口在官网可寻 | CCIT 官网"产品/平台"区提供 EQS 入口链接（到 EQS 前台对应页） | 官网侧 |
| X2 | 对外可展示的"承接概览"只读出口 | EQS 提供公司级只读视图/接口：在管项目数、能力标签、可承接方向，供官网或内部看板取用；不含商机详情、预算、甲方敏感信息 | EQS 出口 API |
| X3 | 承接意向（Lead）外部入口 | 官网"联系/获取报价"表单的结果进入 EQS 商机池，作为一条新商机（来源=官网）供 PMA 处理 | 官网表单 → EQS 商机落库 |
| X4 | 对外联系/报价通道打通 | 从官网提交的咨询，状态在 EQS 商机域可见可追踪（避免官网咨询与 PMA 商机两套孤岛） | EQS 商权入库 |

## 2. EQS 作为 CCIT 交付能力展示的对外信息（非登录公开区）
- D1 公开能力清单：EQS 前台展示"服务/可承接"标签或页面（软件外包、多端小程序、Web、企业数字化、信创等，与 CCIT 实际交付能力一致）。
- D2 公开平台链接/入口索引：EQS 已提供 `GET /api/v1/platform/links`、`/provider/list`、`/theme/list` 等公开端点 —— 可据此支撑官网"产品/入口导航"，复用而非重建。
- D3 版本/状态透明度：`/version/*`、`/config/public` 已有，供官网状态页或运维展示。

## 3. 与 CCIT 公司平台整合（承接用户原话："与 CCIT 网站作为平台的一部分，进行可视化、接入和管理"）
- W1 可视化打通：官网可通过只读出口/Section 嵌入 EQS 概览（在管项目/成果/能力），对内对外一致；（P3，依赖 X2）。
- W2 接入管理：官网带来的 Lead / 咨询统一进 EQS 商机池（X3）；EQS 项目管理结果可在官网对应"项目成果"区做**脱敏展示/链接**。
- W3 双向链接一致性：官网与 EQS 的"联系我们/承接意向"入口指向同一落地（避免两套重复）。

## 4. 落地节奏建议（CTO 可调）
| 阶段 | 内容 | 判据 |
|---|---|---|
| P0 首期 | 官网指向 EQS 入口 + X3 表单落 EQS 商机池 + X2 只读出口雏形 | 官网咨询能进 EQS、PMA 可见 |
| P1 | X4 状态打通 + D1 官网展示 EQS 可承接能力 | 官网展示 EQS 能力与项目脱敏成果 |
| P2 | W1/W2 可视化嵌入与接入管理完善 | 官网 + EQS 形成闭环承接面 |

## 5. 边界与约束
- **生产安全**：EQS 已生产，改动走 EQS 生产审批门（CI/CD tag 授权/备份回滚），不私改现网。
- **凭据/隐私**：公开展示一律脱敏；商机详情、预算、甲方信息只在内部 PMA 域，绝不进公开出口。
- 只读出口、入口打通不得破坏 EQS 既有 auth/pay/delivery 主链路。
- 本清单为立项输入，研发方案与排期归 CTO/项目组，最终以项目立项验收为准。
