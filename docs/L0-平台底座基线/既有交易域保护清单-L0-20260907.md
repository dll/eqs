# 既有交易域保护清单（L0 平台底座 · leader-eqs）

> 文档版本：L0-PROTECT-20260907
> 承接：ccit-cto「EQS-平台底座路线与排期」L0
> 用途：在平台底座 L1 横切加固 / L2 可服务化的后续改动中，明确哪些既有交易能力为**冻结/受控面**，任何触碰即触发门禁。
> 红线总纲（承 ccit-ceo 转 CTO + AGENTS.md）：**资金、dispute、AI 不改；生产写禁；凭据不进 Git；单测 mock；SAR-v10.1 回归不改破；只做加法。**

---

## 1. 保护范围声明

本清单保护的"既有交易域"，是指在 SAR-v10.1 基线上已存在、并在第 2 节列出的**路由端点、持久化模型、落库值规则、状态机迁移**。判定"是否触碰"的机器锚点：
- 路由面锚：`packages/server/cmd/server/main.go` 注册行集合（当前 133）
- 模型面锚：`packages/server/internal/model/db.go` 的 AutoMigrate 清单（当前 28）

> 凡对上述两文件之一产生"增删端点 / 增删模型 / 改动既有落库值或状态机"的改动，即被视为交易域漂移，**须经 CTO 门禁 +《SAR-v10.1-基线复跑报告》回归全绿**后才能合入。

---

## 2. 按域冻结清单（路由 → 保护等级）

### 2.1 🔴 红区 —— 资金 / 争议 / AI（一动即门禁，默认不改）

资金（牵涉金钱流转与落库值，生产写禁最高优先级）：
| 路由 | 说明 |
|------|------|
| `POST /pay/notify/:channel` | 持牌支付回调（公开·验签） |
| `POST /pay/create` | 创建支付 |
| `POST /pay/refund` | 退款 |
| `POST /milestone/:id/settle` | 里程碑结算 |
| `GET /pay/transactions` | 流水 |
| `GET /pay/balance` | 余额 |
| `GET /order/:id/escrow` | 托管台账明细 |
| `GET /admin/escrow/ledger` | 平台对账台账 |
| `GET /admin/commission/list` + `POST /admin/commission/:id/collect` | 佣金 |
| 模型红区 | `PaymentTransaction`、`EscrowLedger`、`CommissionRecord`（落库值/金额字段禁改） |

争议 dispute（状态机 + 专家评审流程）：
| 路由 | 说明 |
|------|------|
| `POST /dispute/create` / `GET /order/:id/disputes` / `GET /dispute/mine` | 创建/列表 |
| `POST /dispute/:id/evidence` / `GET /dispute/:id` / `PUT /dispute/:id` | 证据/详情/变更 |
| `POST /dispute/:id/auto-expert` / `POST /dispute/:id/expert` / `POST /dispute-expert/:id/opinion` / `POST /dispute/:id/close` | 专家指派/意见/结案 |
| 模型红区 | `Dispute`、`DisputeEvidence`、`DisputeExpertAssignment` |
| 后台 | `GET /admin/disputes` |

AI（大模型驱动，行为面敏感）：
| 路由 | 说明 |
|------|------|
| `POST /project/:id/ai-analysis` | 单项目 AI 解析 |
| `POST /admin/ai/project-analysis` | 全量项目 AI 分析 |

### 2.2 🟠 橙区 —— 交易主状态机（不可静默误触）

订单/里程碑/交付/签约（状态机 + 参与方流转）：
| 域 | 路由/条目 |
|----|----------|
| Order | `/order/list`、`/order/:id`(GET/PUT)、`/order/:id/cancel` |
| Milestone | `/order/:id/milestones`(PUT)、`/milestone/:id/deliver`、`/milestone/:id/accept` |
| Deliverable | `models.Deliverable`（随 milestone 落库） |
| Contract | `/contract/templates`、`/order/:id/contract`(POST)、`/contract/:id/sign`、`/contract/:id/download` |
| Bid | `/bid/submit`、`/project/:id/bids`、`/bid/mine`、`/bid/:id/withdraw`、`/bid/:id/select` |
| Project 生命周期 | `/project/:id/withdraw`、`/project/:id/abolish`（软删除积累）等 |
| 打卡/资质 | `AttendanceRecord`、`SupplierQualification`（参与方准入逻辑） |
| 模型区 | `Order`、`PaymentMilestone`、`Deliverable`、`Contract`、`Bid`、`Project`、`AttendanceRecord`、`SupplierQualification` |

> 橙区规则：**状态机迁移值、路由语义、落库枚举**默认不改；若平台底座需横切增强（如鉴权、限流、可观测）应**只做切面加法**，不经由改动状态机常量。

### 2.3 🟡 黄区 —— 直接关联数据（改动需回归兜底，低风险）

| 域 | 条目 |
|----|------|
| 用户/认证 | `User`、`/user/info`、`/auth/*`、`/sms/send` |
| 项目资料 | `ProjectFile`、`FileAnnotation`、`/file/*`、`/annotation/*` |
| 模板 | `DeliveryTemplate`、`ContractTemplate` |
| 社交/通知 | `Review`、`Message`、`Notification`、观看通知相关路由 |
| 案例/计价/会员 | `CaseShowcase`、`/tools/cost-estimate`、`MembershipOrder`、`/member/*` |
| 配置/版本 | `SystemConfig`、`UserSetting`、`SystemVersion`、`/config/*`、`/theme/*`、`/i18n/*`、`/version/*` |
| 审计/日志 | `AuditLog`、`/log/*`、（挂既有 audit 的动作留痕） |
| 服务商 | `Provider`（V8/V9 服务超市，公开浏览） |

黄区规则：允许为平台底座目的做只读/展示增强、字段级加法，但**禁止改坏既有查询语义与既有读写契约**，改动须过既有测试回归。

## 3. 红线操作纪律（承转单 + AGENTS.md，平台底座期间一律适用）

| 红线 | 约束 |
|------|------|
| **资金/dispute/AI 不改** | 红区路由与模型默认冻结；如需加固仅允许外层中间件/切面加法，不进入 handler 资金-状态逻辑内部 |
| **只做加法** | 平台底座 L1/L2 一律以新增文件/新端点/适配层方式落位，不在既有交易域文件内做结构破坏 |
| **生产写禁** | 任何命令/测试/迁移一律不得对生产库写入；复跑与单测仅在内存 SQLite / mock 环境 |
| **凭据不进 Git** | `.env`、`deploy/.env*`、微信/支付秘钥均不得入库；新适配对密钥只读环境变量 |
| **单测 mock** | 新逻辑依赖的 Redis/支付/短信等外部均 mock，不依赖真实外部服务 |
| **SAR-v10.1 回归不改破** | 每笔合入前必跑 `go build`、`go vet`、`go test -count=1 -p 1 ./...`，7 包全绿 |
| **模型/路由锚不动** | `main.go` 注册行集合与 `model/db.go` AutoMigrate 清单，任何增删改走 CTO 门禁 |

---

## 4. 触发门禁（CTO）的判据

当后续 PR/改动满足以下任一，即须先经 ccit-cto 门禁评估而非直接合入：
1. `main.go` 注册行集合变化（路由增/删/改）——即使是"加法"新增端点，若属红/橙区也要门禁；
2. `model/db.go` AutoMigrate 清单变化，或红区模型的字段/落库值变化；
3. 触碰红区（资金/dispute/AI）的任意 handler 逻辑；
4. 改动既有交易状态机迁移值或落库枚举含义。

> 判定工具：`git diff SAR-v10.1锚点 HEAD -- packages/server/cmd/server/main.go packages/server/internal/model/` 若输出非空，视为交易域面漂移信号，交由 CTO 复核。
