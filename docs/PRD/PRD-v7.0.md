## 1. 系统配置中心

### 1.1 概述

系统配置中心（System Configuration Center）是 V7.0 的核心基础设施，统一管理所有**非功能性参数与功能开关**，由管理员（user_type=3）通过后台维护，前端按需读取。

### 1.2 配置项分类

| 分类 | 配置键示例 | 说明 |
|------|-----------|------|
| 主题配置 | `theme.default`、`theme.allowUser`、`theme.allowProject` | 系统主题相关 |
| 国际化 | `i18n.default`、`i18n.allowSwitch` | 语言相关 |
| 多端 | `multiplatform.enabled`、`multiplatform.urls` | 多端切换 |
| 版本 | `version.current`、`version.updateUrl`、`version.checkInterval` | 版本与更新 |
| 演示数据 | `demo.enabled`、`demo.seedMode` | 演示数据开关 |
| 系统 | `system.maintenanceMode`、`system.maintenanceMessage` | 维护模式等 |

### 1.3 功能要求

- **CRUD**：管理员可创建、读取、更新、删除配置项。
- **批量读取**：前端通过 `GET /api/v1/config/public` 获取公开配置（不含敏感项）。
- **类型安全**：每个配置项声明类型（string/int/bool/json）。
- **缓存**：配置读取走内存缓存，变更后失效。
- **审计**：配置变更写入审计日志。

### 1.4 权限模型

- 管理员（user_type=3）：全部配置读写。
- 普通用户（甲方/服务方）：仅可读取公开配置，可写**用户级偏好**（主题、语言），不可写系统配置。

## 2. 系统主题

### 2.1 主题模式

| 主题 | 标识 | 说明 |
|------|------|------|
| 打印主题（默认） | `print` | 白底黑字、无深色背景、适合截图与打印，对比度高 |
| 深色主题 | `dark` | 深色背景、浅色文字，适合夜间使用 |
| 浅色主题 | `light` | 标准浅色界面 |

### 2.2 主题切换规则

| 规则 | 说明 |
|------|------|
| 系统默认 | 默认 `print`（打印主题），保证白底黑字清晰截图打印 |
| 用户自动切换 | 用户可设置偏好主题；系统根据**系统设置中的明暗偏好**或**手动选择**自动应用 |
| 项目主题 | 项目详情页可随机/选择主题（如造价项目用浅色、监理项目用深色），项目级主题覆盖用户级 |
| 切换方式 | 用户中心提供主题切换入口；项目详情提供项目主题选择 |

### 2.3 实现要求

- 主题通过 CSS 变量（`--bg-color`、`--text-color` 等）实现，运行时切换。
- 用户偏好存入 `user_settings` 表。
- 项目主题存入 `projects.theme` 字段。
- 打印主题需确保 `@media print` 样式为白底黑字。

## 3. 国际化

### 3.1 支持语言

| 语言 | 代码 | 说明 |
|------|------|------|
| 中文 | `zh-CN` | 默认 |
| 英文 | `en-US` | 英语 |

### 3.2 切换规则

- 系统默认语言：`zh-CN`（可由配置 `i18n.default` 修改）。
- 用户语言偏好：存入 `user_settings.lang`，登录后自动应用。
- 切换入口：登录页、用户中心提供语言切换。
- 多端一致：H5/小程序/App 共用语言偏好。

### 3.3 实现要求

- 前端使用 Vue i18n（client 与 admin 均接入）。
- 文案集中管理于 `locales/zh-CN.json`、`locales/en-US.json`。
- 时间/金额/数字格式化遵循语言区域。
- 后端错误消息提供 `message_key` 供前端翻译，或直接返回双语。

## 4. 多端切换

### 4.1 支持端

| 端 | 标识 | 说明 |
|----|------|------|
| H5 | `h5` | 浏览器访问 |
| 微信小程序 | `mp-weixin` | 微信内 |
| iOS App | `app-ios` | 苹果设备 |
| Android App | `app-android` | 安卓设备 |

### 4.2 切换规则

- 同一账号在任一端登录后，会话（token）在多端共用。
- 端间切换：用户中心提供"其他端访问"入口（展示各端访问二维码/链接）。
- 多端数据一致：通过统一后端 API 保证。
- 配置 `multiplatform.urls` 维护各端访问地址。

### 4.3 实现要求

- uni-app 一套代码多端编译。
- 提供 `GET /api/v1/platform/links` 返回各端访问地址（由配置驱动）。
- 小程序端登录复用同一 JWT 体系。

## 5. 版本检查与更新

### 5.1 版本模型

| 字段 | 说明 |
|------|------|
| version | 语义化版本号，如 `1.0.0` |
| build | 构建号 |
| updateUrl | 更新下载地址 |
| releaseNotes | 更新说明 |
| mandatory | 是否强制更新 |

### 5.2 检查规则

- 前端启动时调用 `GET /api/v1/version/check?current=1.0.0` 检查版本。
- 若有新版本：非强制更新弹提示；强制更新弹阻断框。
- 检查间隔：`version.checkInterval`（默认 6 小时）。
- 后台提供版本记录管理（管理员上传新版本信息）。

### 5.3 实现要求

- 版本信息存 `system_versions` 表。
- `GET /api/v1/version/latest` 返回最新版本信息。
- H5 更新：提示后刷新并清缓存；小程序/App：跳转更新地址。

## 6. 演示数据管理

### 6.1 需求澄清

> 演示数据功能已实现为 admin API（`/admin/demo/seed` 等），但**管理后台界面缺少入口**，管理员无法直观操作。V7.0 将演示数据功能纳入**系统配置中心**，在后台提供管理界面入口与开关。

### 6.2 功能要求

| 功能 | 说明 |
|------|------|
| 演示数据开关 | `demo.enabled` 控制演示数据是否可用 |
| 生成演示数据 | 后台按钮触发 `POST /admin/demo/seed?mode=demo` |
| 清理演示数据 | 后台按钮触发 `POST /admin/demo/clean` |
| 模式选择 | demo/test/training 三种模式 |
| 状态展示 | 展示当前演示数据统计（用户/项目/订单/争议数） |

### 6.3 权限

- 仅管理员可操作演示数据。
- 生成/清理操作写入审计日志。

|------|------|

- 版本检查接口限流。

## 9. API 设计

### 9.6 演示数据

## 10. UI/UX 规范

### 10.1 主题实现

- 使用 CSS 变量定义主题色板。
- 打印主题：`--bg-color: #fff; --text-color: #000;`。

- 文案库覆盖：导航、表单、按钮、提示、错误消息。

### 10.3 配置中心界面

- 后台新增"系统配置"菜单，支持分类筛选与编辑。
- 演示数据管理集成在系统配置中。
