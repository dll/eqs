## 0. 背景与目标（写给 EQS 研发组）

原 EQS 定位为**工程服务智慧交易与协作平台**（需求方↔造价/地勘/监理/设计服务方，含发布需求→匹配/抢单→签约→交付→结算→信用闭环），已发布上线、处于迭代中。

现 CCIT 公司指定 EQS 同时作为 **公司级项目经理助理（ccit-pma）的承载/运营后台**，支撑 PMA 的**软件商机承接与项目全生命周期管理**。二者不互斥：EQS 既保留对外交付的交易/协作业务，又新增对内运营的**商机与项目管控域**。

本清单界定**为支撑 PMA 运营而新增/改动的功能范围**。是否与既有"工程服务交易"域融合、或作为独立运营模块并存，由 EQS 研发组在方案中裁定并说明互不影响理由。

## 1. 角色与用户（PMA 域）

| 角色 | 使用面 | 权限 |
|---|---|---|
| **ccit-pma（AI，主导方）** | 全部模块 | 录入、筛选、提案、推进、运维 |
| **真人 PM（张洁）** | 商机录入 + 决策 + 线下单上传 | 新增商机、查看、评估、决策意见 |
| **OPC（刘东良）** | 只读简报 + 可视化浏览 + 定案审批 | 查看全部、审批/打回、查看建议 |
| **其他职能（CTO/ENV/OPS 等）** | 项目接入后协办 | 按需只读或工单处理 |

> 飞书推送真人 = 推送给 OPC、真人 PM；见 §6。

## 2. 功能模块总览

```
A. 商机采集         爬/收国内外软件项目发包信息
B. 商机筛选与提案   PMA 筛选 → CCIT可承接提案
C. 定案与立项        OPC 定案 → 生成项目
D. 项目全生命周期    范围/里程碑/排期/风险/验收/交付/复盘
E. 可视化与简报      看板 + OPC 简报 + 浏览
F. 推送（飞书/公司平台）
G. 平台自身运维      PMA 自主运维入口
```

## 3. 功能详情

### A. 商机采集
- A1 线上源管理：可维护商机源清单（**推荐启动集**：国内 解放号/开源众包/程序员客栈/程聚宝/一品威客/猪八戒；海外 Upwork/Fiverr/Toptal；依可用性增删、支持禁用失效源）。
- A2 采集任务：对每个源可配置**每日抓取/拉取**策略与频控（防封），失败可重试、记录。
- A3 落地存储：抓到的原始项目信息入库（来源 / 标题 / 摘要 / 预算 / 周期 / 甲方 / 发单时间 / 技术栈 / 原文链接 / 抓取时间），可去重。
- A4 **线下商机录入**（真人 PM 张洁）：提供上传入口（表单/粘贴/拍照/文件），登记到同一商机库，标记"线下来源"。
- > 采集方式：因各源反爬/结构差异，研发组可实现"RSS/开放接口 + 规则化页抓取 + 半自动导入"组合，先跑通最小闭环（能进 A3 入库即可），再扩展覆盖度。

### B. 商机筛选与提案
- B1 字段与标签化：预算、类型（软件/外包/政企/信创/小程序/Web…）、技术栈、地区、语言、可信度预判。
- B2 筛选规则：可按 CCIT 承接能力预设过滤（预算下限、类型黑/白名单、甲方可信标记），支持人工微调。
- B3 **提案生成**：对候选商机按统一模板产出（来源 / 需求摘要 / 甲方可信度与风险 / 预估范围与报价区间草案 / CCIT 能力匹配 / 建议取舍：跟进/观望/放弃）。
- B4 状态流转候选：`新线索 → 已筛选 → 已提案 → 已上报 → 跟进中`，人工可回退。
- > PMA 只做筛选+提案，不报价/应单/签约（系统侧不提供一键应单；报价草案仅作内部评估参考）。

### C. 定案与立项
- C1 定案：OPC 对提案给出 **通过 / 打回 / 待补充**；通过即生成内部项目。
- C2 立项记录：编号、来源商机绑定、主张范围、拟定 PM（默认 PMA）、审批留痕（谁/何时/结论）。

### D. 项目全生命周期管理
- D1 阶段模型：`立项 → 需求/范围 → 里程碑/排期 → 交付协调 → 验收 → 结项 → 复盘归档`。
- D2 范围与需求：记录需求文档/验收标准（链到仓库/文档），变更记变更记录。
- D3 里程碑与排期：里程碑列表、起止、状态；可关联外部交付资源（研发组/项目级 Agent 只读或工单）。
- D4 风险清单：风险条目（等级/描述/缓解/责任）/ 红黄绿灯，触发升级。
- D5 进度与阶段验收：阶段进度状态、OPC/真人可验收打勾。
- D6 交付/结项：交付物清单、结项结论、复盘要点归档。

### E. 可视化与简报
- E1 看板（管理/浏览）：商机漏斗、项目看板（按阶段卡片）、里程碑甘特/列表、风险红黄灯、近 7/30 天新增。
- E2 **OPC 简报**：一键生成简明简报（新增商机、待定案、在管项目、风险、需关注），供"只读简报即了解运行"。
- E3 外部公司平台出口：供 CCIT 公司平台（见 §6 通道）展示/接入的可引用视图或只读口。

### F. 推送（三通道）
- F1 EQS 平台内：以上看板/项目/简报即在 EQS 内可视化，为默认展示面。
- F2 **飞书推送真人**：待办或里程碑事件推送 OPC / 真人 PM（如：有待定案提案、项目风险升红、阶段验收待办）。
- F3 **CCIT 公司平台整合**：与独立公司网站（www.ccit-agent.cn 域，属公司站改/另立项）打通或预留接口；本清单仅要求 EQS 侧具备可被引用的只读出口/接口约定。

### G. 平台自身运维（供 PMA 自主运维）
- G1 运维状态：采集任务运行状况、失败重试、库健康、通道连接状态。
- G2 数据维护：源启停、字段/标签维护、去重与冗余清理、数据导出/备份入口。
- G3 审计留痕：商机与项目关键动作留痕（谁/何时/改什么），可追溯、不可被普通账号删改审计。

## 4. 建议落地节奏（EQS 研发组可调）

| 阶段 | 内容 | 完成判据（面向 PMA 最小可用） |
|---|---|---|
| **MVP（先跑通闭环）** | A 最小采集（1–2 个易接源可入库）+ 线下录入 + B 筛选/提案 + C 定案 + D 基础生命周期（立项–结项）+ E1 看板 + E2 简报 + F1 平台内展示 | 能人工挂 1–2 条商机→提案→定案→生成项目→看板可见 |
| **P1（自动化与推送）** | A 多源/频控稳定 + F2 飞书推真人 + E2 简报成文 | 每日自动采集入库、待定案自动推 OPC |
| **P2（管理深化）** | D 里程碑/风险/验收完整 + G 运维面板 | PMA 可纯通过平台管理一批真实项目 |
| **P3（公司平台打通）** | F3 与公司平台整合 + E3 出口 | 商机在 CCIT 公司平台可视 |

> 此处只给骨架，具体到功能点/验收由 EQS 项目按自身流程细化与排期。

## 5. 边界与约束（写给研发组，勿越）
- **生产安全**：EQS 已上线，改动走 EQS 既有生产审批门（含 CI/CD、tag 授权、备份回滚）；不得私改已发布生产。
- **凭据**：商机源账号/平台凭据、推送密钥按 EQS 外部接入指南管理，不进 Git、不进聊天、不留文档明文。
- **范围尊重**：本清单仅新增运营/商机域与必要接口，不要求重写原工程服务交易业务；两者如何共存由研发组方案裁定。
- **不代签单**：系统不提供一键应单/报价对外提交；报价草案仅供内部评估。
- **外部爬取合规**：遵守目标平台条款/robots，设频控，避免过度抓取；优先公开接口/订阅。
