# EQS AOC Adapter 部署与回滚

## 部署

1. 使用与现有 EQS 服务相同的配置和数据库连接，不新增数据库表或写入操作。
2. 在 CI 中执行 `go test ./...`、`go test -cover ./internal/adapter` 和 `go build ./cmd/server`。
3. 发布现有服务二进制并按现有 systemd/Nginx 流程重启；适配器路由为 `/adapter/v1`。
4. 发布后执行 `GET /adapter/v1/health`，确认 `status=healthy`、`project_id=eqs`、`schema_version=v1`。
5. 观察 5 分钟错误率和 P95；出现数据库连接异常时接口应返回 HTTP 503 与 `status=unavailable`。

## 回滚

1. 停止发布流程，保留当前数据库，不执行数据回滚（本适配器只读）。
2. 恢复上一个稳定版本的 EQS 服务二进制并按现有流程重启。
3. 确认原有 `/api/v1` 业务接口可用；若回滚版本不包含适配器，以原业务可用为准。
4. 将发布前后的健康检查、测试报告和 Git 提交记录归档，说明适配器未改变业务数据。

## 验收与安全

- 非 GET/HEAD 请求返回 405。
- `project_id` 不是 `eqs` 时返回 403。
- 手机号、证件号、金额、详细地址、服务方名称和文件原文不通过适配器返回。
- 响应统一携带 `project_id`、`source`、`observed_at`、`schema_version`。
